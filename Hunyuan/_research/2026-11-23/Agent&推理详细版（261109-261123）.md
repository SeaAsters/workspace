## 三、⭐ 专题：DFly2 —— 稀疏注意力旗舰的投机解码层

> 为什么单独立节：DFly2 是 Hy4 与 Hy4-flash **共用的新投机解码器**，替代了 Hy3/Hy4-preview 的原生 MTP；它同时牵动模型架构（5 层 drafter）、训练（AngelSpec）、serving（D-cut、PD 分离）与 NPU 适配四条线。

### 3.1 谱系：MTP → DFly → DFly2

| 代际 | 载体 | 形态 | 参数 |
|---|---|---|---|
| 原生 MTP | Hy3 / Hy4-preview | 单个原生 MTP 层（推理时递归复用） | 10B 总参 / 0.7B 激活（preview） |
| **DFly** | Hy3-A21B（AngelSpec 论文） | **块并行扩散 drafter**（block-parallel diffusion） | 论文未给参数，平均接受长度 4.79 tokens |
| **DFly2** | **Hy4 / Hy4-flash** | 5 层块并行 drafter + **KV Share + Index Share** | **3.3B**（Hy4）/ **0.85B**（flash） |

- **DFly 的来源**：AngelSpec（`arXiv 2607.25852`，腾讯，Hong Liu 等 13 人，7-28 首发）——"统一 MTP 与块并行扩散的训练框架"。论文在 **Hy3-A21B** 上验证 DFly：相对 DFlash（前代扩散 drafter）**平均接受长度 +30%**、整体平均接受长度 **4.79 tokens**、并发 4~64 全区间吞吐最高、**1.98–2.40×** vs 自回归、比 DFlash 吞吐高 **10.5–11.8%**。
- **DFly2 相对 DFly 的新增**：**KV Share + Index Share**（复用 Hy4 DSA 层的 KV cache 与 indexer 的 top-2,048 选择）——Hy4 稀疏注意力架构带来的特有优化，论文版 DFly（Hy3 上）没有。**"2" 的本质 = 把 drafter 嫁接到稀疏 KV 上**。

### 3.2 机制：架构图逐块解读（`assets/dfly2.png`）

```
Target Model（冻结）
 ├─ KV(k) / Index(k)  ──┐   ← DSA 层的 KV cache + indexer 选出的 top-2048 位置
 ├─ KV(m) / Index(m)  ──┤   （图例：白框=From target reused/init；蓝块=Target DSA indexer top-k）
 ├─ KV(l) / Index(l)  ──┤
 └─ h(last) ────────────┴─→ Gated Fusion（门控，条件=t5，最后一个已接受的 token）
                              ↓
        ┌──────── DFly2（5 层，图示 3 层）────────┐
        │  Transformer Block  ← causal attn · init from layer m · reuse target KV
        │  Transformer Block  ← 同上
        │  Transformer Block  ← 同上
        │        ↓ z6 / z7 / z8（并行的逐位置预测）
        │  Hidden-Correction（自回归修正头，条件=前一个已选 token）
        │        ↓ t6 / t7 / t8（被修正后的起草 token）
        └──────────────────────────────────────────┘
输入侧：t5 + 三个 Mask（待起草位置一次并行输入）
```

四个关键设计点：

1. **块并行 backbone**：三个 draft 位置（t6/t7/t8）在**一次前向**里并行预测——"扩散式"（block-parallel diffusion）的效率来源：draft 延迟被长块摊销。
2. **Hybrid target-conditioning**（论文创新一）：每层 draft block **接一个对应深度的 target DSA 层视角**（"init from layer m"），而不是全部共享同一全局投影（DFlash 是 shared projection；DFly 结合 DFlare 的 layer-specific target views）——不同深度用适合自身的 target 特征。
3. **Hidden-Correction 自回归头**（论文创新二）：块并行的问题是**位置间独立预测、后缀不连贯**；修正头以**前一个已选 token 为条件**给每个位置做一次轻量修正（z6→t6，t6 再条件化 z7→t7……）——"把逐位置边际预测变成前缀条件分布，同时保留单次并行 backbone"（论文原话）。这就是 `t6` 既出现在右上角又回流进修正头的含义。
4. **KV Share + Index Share**（DFly2 新增）：
   - **KV Share**：draft 层不建自己的 KV cache，直接读 target 对应 DSA 层的 KV——**零额外 KV 内存**；
   - **Index Share**：连"看哪些 key"都复用 target indexer 选出的 top-2,048 位置——**每 draft token 至多看 ~2K keys，成本恒定**，与 1M 上下文解耦。

> **一句话**：普通 drafter 在长上下文下"越来越贵"（draft attention ∝ L，还要自带 KV）；DFly2 把 draft 变成"寄生在 target 稀疏 KV 上的 5 层小网"，**成本对上下文长度求导为零**。

### 3.3 为什么 Hy4 必须换掉 MTP：论文给出的"暴露偏差"证据

AngelSpec 论文对 MTP 的诊断（理解换代的钥匙）：

- MTP 训练是**单次 teacher-forcing**（真实 token + 干净 hidden），推理却要**递归复用同一块**（自己的预测 + 递归 hidden + 增长的 draft KV）；
- 误差随深度累积：**第 2/3 个 draft 位置的接受率显著低于第 1 个**；
- 解法 **TTT（Training-Time Test）+ 共享参数多深度训练**：同一物理 MTP 块自回归展开 D 步，每个逻辑深度 k 由自己的 shifted future-token 目标监督 + memory-efficient distillation 对齐冻结 target 分布；
- 效果（Hy3 MTP，T=0）：平均接受率 **52.8% → 66.4%**。

> 但即使 TTT 修好了 MTP，它仍是"短程"drafter（论文定位：MTP 面向高熵对话，块并行面向代码/数学长可预测段）。Hy4 作为"coding/agent/finance"旗舰选择 DFly2 而非修好的 MTP，说明**它押注的是长可预测段的工作负载**——这也解释了为什么 flash 的 RL 要"削减输出 token 50%"：减少长程不可预测的输出，留下可被投机加速的确定性部分。

### 3.4 训练侧：AngelSpec 的三层特化 + 工程件

| 层 | 做法 |
|---|---|
| 数据特化 | **MTP 训对话数据**（高熵、开放域）、**块扩散 drafter 训代码+数学**（长可预测延续）——不再追求"一个通用 drafter"，而是"结构 × 数据"协同特化 |
| 架构特化 | DFly（hybrid conditioning + AR 修正头） |
| 推理特化 | **D-cut**（见 §3.5） |
| 工程 | **disaggregated hidden-state 生成**：推理引擎产出 target hidden states，**流式直送训练 worker**；document-aware sequence packing；**evaluation server 在线测真实接受率** |

**开源面**：AngelSpec 训练代码 + **Hy3-A21B 的 MTP / DFly drafter 权重**（HF `AngelSlim/angelspec` collection）。Hy4/DFly2 的训练代码是否同样开源——README 未说明。

### 3.5 D-cut：把"验证深度"变成 batch 级调度资源

- **观察**：接受长度随域/请求/decode step 变化；验证额外 token 的成本随**在线负载与硬件**变化。固定验证深度要么在轻载时浪费可预测 draft，要么在高并发时把 batch 容量浪费在低价值后缀上。
- **机制**：把 target 验证当作**跨请求共享的 batch 级资源**——按前缀置信度把算力重分配给高置信前缀，结合 **profiled 运行时成本模型**自适应验证深度（保守时保留长 draft，验证变贵时激进剪枝）。
- **数字**：生产流量、**并发 64** 下，D-cut 相对不剪枝的 DFly **吞吐 +15.7%**。
- **论文自述局限**：selector/packing 逻辑与 piecewise CUDA graph 带来开销；未来做 per-batch/ratio 的 full CUDA graph、把预算选择移出关键路径。

> **洞察**：投机解码在这一代被拆成"**模型问题（drafter 结构）+ 调度问题（验证预算）**"两半。D-cut 与 continuous batching / PD 分离同层——**serving 系统开始把"接受率"当一等调度信号**。

| 4 | **DFly2 训练代码未开源** | README 只指向 AngelSpec 仓库；AngleSpec 开源的是 Hy3-A21B 的 MTP/DFly drafter | 自训 DFly2 可用 AngelSpec 框架，但**不是开箱即用** |
| 5 | **D-cut 的实现开销** | 论文自述 selector/packing + piecewise CUDA graph 开销 | +15.7% 是净收益；低并发/小 batch 可能得不偿失——**按负载实测** |
| 6 | **drafter 占比** | 3.3B / 770B = **0.43%**；flash 0.85B / 224B = 0.38% | 比 MTP（10B/770B = 1.3% 总参）更轻，但比 MTP 的 0.7B **激活**更重——**总参换激活**：DFly2 每 draft 步激活更多参数，靠"块并行摊销 + 恒定 KV 成本"赚回来 |

### 3.8 DFly2 的三条洞察

> **㉓ 投机解码进入"按负载选 drafter"阶段**：AngelSpec 的核心论点是**没有一种 drafter 通吃**——MTP 适合高熵对话、块扩散适合代码数学。Hy4 全家（Hy4 = 代码/agent 旗舰、flash = 日常高频）都选 DFly2，说明混元的**目标负载被判定为"长可预测段为主"**；同时 AngelSpec 统一框架保留 MTP 训练路径，**serving 层按负载切 drafter 可能成为下一步**。

> **㉔ 稀疏注意力的收益被"两次收割"**：第一次是 prefill（IndexCache/top-2048 让 1M 上下文可算），第二次是 **decode 的投机环节**（DFly2 的 Index Share 让 draft 成本恒定）。**DSA 架构让 drafter 从"独立小模型"退化为"target 稀疏 KV 的寄生层"**——这是"架构决定推理经济性"的最直接案例，也解释了 FlashTopK 这类 selection 内核为什么会成为基础设施（drafter 也要选 top-k）。

> **㉕ DFly2 是最难移植到 NPU 的组件**：它要求 ① draft 层能直接读 target 的 KV cache 与 indexer 输出（跨模型状态共享）② 块并行 backbone + AR 修正头的混合执行 ③ D-cut 的 batch 级验证调度。商发分支现有 MTP 路径（10 月）**无法直接迁移**——NPU 侧要么等 vLLM-Ascend 的 DFLY 实现，要么先跑非投机路径保底。

## 十、结论

本窗口一句话：**混元把 11-04 的开源承诺全部兑现，并用 flash 把开源节奏拉回"两天"**。技术上三件事：① **DFly2 替代 MTP**——5 层块并行 drafter + Hybrid target-conditioning + Hidden-Correction 自回归头 + **KV/Index Share**（draft 成本对上下文长度求导为零）+ **D-cut**（验证的 batch 级调度），使稀疏注意力的收益从 prefill 延伸到 decode 的投机环节（§三）；② **flash 用 LatentMoE + Engram + 1:3 混合注意力**把日常任务成本压到 Hy4 的 1/20（WorkIndex 42.1 略超 preview），"旗舰保上限、flash 保日常"的双模型结构成型；③ **HF 一次上架 20 个 WeMM-Video 仓库 + NVFP4 + FlashTopK SM100**，"Blackwell 就绪"成为隐性主题。

必须记录的暗线：**正式版权重 License 从 Apache-2.0 收窄为带 MaaS 条款的 Tencent Hy License**（$50M 营收 / 1 亿 MAU 门槛，内部使用豁免）。

**Agent 侧本窗口增量很小**（UniRL 算法新增 AROPD、agentic 零改动；Hy-Memory 稳定性硬化；DiagSafe 扩 reasoning）——与推理侧的大动作形成对比。

**昇腾侧**：权重已可拉取、官方 vLLM-Ascend 指南已合入，进入**实机验证与重同步窗口**（P0）；专项评估 **DFly2 的 NPU 可行性**（P0/P1，短期先跑非投机保底）；对外服务先过 License 条款（P0 合规）。
