### 2.3 架构确认：正式版 = HY4-VL 形态（商发分支推断被证实）

HF 模型卡 `architectures` = **`HYV4VLForConditionalGeneration`**——与本地商发分支 10 月注册的架构名（`vllm_ascend/patch/hy4_vl/`）**逐字一致**。上轮"Hy4 正式版视觉能力的载体是 Hy4-VL 形态"的推断成立。

正式版完整规格（README 规格表照抄）：

| 项 | 值 |
|---|---|
| 总参数（不含 ViT/adapter/DFly2） | **770B** |
| 激活参数 | **Text 49B + Vision 1.23B** |
| ViT | **1.23B**：40 层、hidden 1,536、FFN 6,144、16 heads、**patch 16×16**、位置嵌入 128×128、2×2 merge |
| DFly2 drafter | **3.3B / 5 层**（**替代 preview 的 MTP 层**） |
| 上下文 | 1,048,576（1M） |
| Backbone | 78 层（1 dense + 77 MoE）、hidden 6,144、词表 120,832、**iHC 4 条残差流** |
| 注意力 | **Gated DSA + IndexCache**；MLA（64 heads、q_lora 2,048、kv_lora 512）；**indexer 32 heads×128、选 top-2,048 token** |

> ⚠️ **本地商发分支的视觉塔规格（27 层 / hidden 1,152）不等于正式版 ViT（40 层 / 1,536）**，反而与 **flash 的视觉塔**（27 层 / 1,152，SigLIP2-So400m 改版）一致——商发分支 10 月适配的是当时内部版本的配置，重同步时必须核对（见 §六）。

### 2.4 DFly2：稀疏注意力模型的第三条投机路线

| 项 | 事实（README"DFly2 for Speculative Decoding"节） |
|---|---|
| 机制 | 每层 drafter **复用对应 DSA 层的 KV cache（KV Share）与 indexer 选出的 top-2,048 位置（Index Share）** |
| 训练 | 用 **AngelSpec** 训练 |
| 优势 ① | **常数成本**：每个 draft token 至多看 ~2K keys，**不随上下文长度增长** |
| 优势 ② | **零额外 KV 内存**：drafter 不单独维护 KV cache |
| 优势 ③ | **PD 分离就绪**：不参与 prefill；P→D 传输只多一个末层 hidden state |
| 部署 | vLLM `--speculative-config '{"num_speculative_tokens":5,"method":"dfly"}'`；SGLang `--speculative-algorithm DFLY`（两边均已内置，非社区补丁） |

> **定位**：与 ① 原生 MTP（preview/Hy3）、② DSpine（腾讯其他团队，并行起草）并列的**第三条投机路线**——专为**稀疏注意力**设计：draft 直接吃 indexer 的选择结果，因此 draft 成本与上下文解耦。MTP 在 1M 上下文下 draft 越来越贵，DFly2 则恒定——这是"稀疏架构套利"从 prefill 延伸到 decode。

### 2.7 部署（照抄，可直接用）

```bash
# vLLM（官方镜像 vllm/vllm-openai:hy4）
docker run --gpus all --privileged --ipc=host -p 8000:8000 \
  -v ~/.cache/huggingface:/root/.cache/huggingface \
  -e VLLM_USE_RUST_FRONTEND=1 \
  vllm/vllm-openai:hy4 tencent/Hy4-FP8 \
  --dtype bfloat16 --tensor-parallel-size 8 \
  --limit-mm-per-prompt '{"image":1,"video":0}' \
  --enable-auto-tool-choice --reasoning-parser hy_v4 --tool-call-parser hy_v4 \
  --speculative-config '{"num_speculative_tokens":5,"method":"dfly"}' \
  --attention-backend FLASHMLA_SPARSE --port 8000 --served-model-name hy4

# SGLang（官方镜像 lmsysorg/sglang:hy4，multi-arch）
sglang serve --model-path tencent/Hy4-FP8 --tp 8 \
  --speculative-algorithm DFLY --port 8000 --served-model-name hy4
```

推理参数：`temperature=0.9 / top_p=1.0`；`reasoning_effort` 取 `"no_think"`（直答）或 `"high"`（默认深思考）。另有 vLLM Recipe（recipes.vllm.ai/tencent/Hy4）与 SGLang Cookbook 双路径、finetune 管线（`finetune/README.md`）。

### 3.2 规格：224B 总参 / 12B 激活的构成

| 项 | 值（README 规格表） |
|---|---|
| 总参数 | **224B** = backbone **155.5B** + **Engram 63.5B** + ViT 0.43B + DFly2 0.85B |
| 激活 | **Text 11.3B + Vision 0.43B**（官方口径"12B 激活"） |
| Backbone | 42 层（1 dense + 41 MoE）、hidden **3,072**、词表 120,832、iHC 4 流 |
| 上下文 | 1M（1,048,576） |
| 视觉 | ViT **0.43B：27 层、hidden 1,152**、FFN 4,304、16 heads、patch 16、pos 128×128、2×2 merge（**SigLIP2-So400m-Patch16-Res512 改版**） |
| 投机 | DFly2 **0.85B / 5 层**（同 KV Share + Index Share；索引为"压缩 indexer 的 ≤2,048 选择"） |

**三项新架构**（README 明确列出，均为混元首次）：

| # | 架构 | 细节 |
|---|---|---|
| ① | **混合注意力** | Sparse（IndexPool）与 **SWA 按 1:3 交错**：层模式 `2 × Sparse → 10 × (3 × SWA → Sparse)`（12 稀疏层 / 30 SWA 层）；稀疏层组级选 ≤2,048 token；**SWA 窗 512 token**（511 前文 + 当前）；RoPE base 稀疏层 1e7 / SWA 层 1e4；**Interleaved MRoPE** |
| ② | **LatentMoE** | 路由专家在 **1,536 维潜空间**工作；**512 路由专家取 16** + 1 共享；专家 FFN 1,536 |
| ③ | **Engram N-gram embedding** | **bigram + trigram** 多头哈希检索；每阶 **8 heads × 10.3M 哈希词表/head**，每阶 768 维（8×96）；注入 backbone **第 1/11/21/31 层**；嵌入表合计 **63.4B 参数** |

> **读法**：三项都是"用参数换计算/显存"的路数——Engram 用 63.5B 参数表把 n-gram 知识从 attention 里挪出来（检索代替计算）；LatentMoE 把专家计算压到 1,536 维潜空间；1:3 稀疏+SWA 把 3/4 的层压到 512 窗。**结果就是 KV cache 只有 Hy4 的 1/6**——这是"日常任务大批量高并发"负载的正确取舍。

### 3.3 效率主张与评测（README"Practicality and Cost Efficiency"）

| 维度 | 事实 |
|---|---|
| Pre-training | 三项架构 → **KV cache 仅 Hy3 的 1/24、Hy4 的 1/6**；scaling ladder 实验保证性能 |
| Post-training | **从 Hy4 自蒸馏**建立通用智能 + RL **削减平均端到端输出 token 50%** |
| Evaluation | 自建 **WorkIndex**（8 个内部工作集：PPT 制作/修改/人机双写、Markdown 双写、文档编辑、表格修复、音视频处理、视觉理解）+ 7 个公开 Agent 集（DeepSWE、ProgramBench、Terminal-Bench 4.0、APEX-Agents、AutomationBench、HLE、OSWorld 2.1）；关注"交付物质量/单轮输出长度/任务周转时间"而非脱离工作的公开分 |
| Inference | **megakernel + 4-bit 量化 + DFly2 → 解码 >150 tokens/s** |
| 效果 | **WorkIndex 42.1 vs Hy4 preview 39.7**——**性能略超 770B 的 preview** |
| 成本 | 单任务成本 = preview 的 **1/13**、Hy4 的 **1/20**、DeepSeek-V4.1-Flash-1017 的 **1/8**（Max 档峰时价） |
| 人评 | 85 位 WorkBuddy 内部用户、27 类 259 任务盲测：满意度**接近 Claude Haiku 5.5**，成本最低、时长最短 |
| base 评测 | 与 Hy4-Base 同表：MMLU 88.7 / C-Eval 92.0 / SimpleQA 37.5 / MMMU-Pro 52.0——全面低于 Hy4-Base，差距最大在 SimpleQA（37.5 vs 57.2） |

> ⚠️ 口径：WorkIndex 是**自建内部集**，"42.1 略超 preview" 与 "成本 1/20" 都出自官方；"满意度接近 Haiku 5.5"是内部盲测表述，非第三方。

## 六、本地 vllm-ascend-hy4（商发分支概览与重同步需求）

> 本地商发分支 `hy4-v0.30.0`（基于上游 v0.30.0rc1，127 commits，其中 11 个 HY4 相关）在 10 月已为 Hy4（文本 + 多模态）备好昇腾 day0 底座；本窗口权重正式开源后，进入**核对与重同步阶段**。

- **架构名已对上**：商发分支注册的 `HYV4VLForConditionalGeneration` / `hy_v4_vl` config 与开源权重的 `architectures` 逐字一致——接入面无结构性变化，**权重可以直接进入既有加载路径**。
- **⚠️ 视觉塔规格不一致（重同步第一优先）**：商发分支 10 月验证报告的视觉塔为 **27 层 / hidden 1,152 / 16 heads×72**；开源 Hy4 正式版 ViT 为 **40 层 / hidden 1,536 / FFN 6,144**；而与商发分支规格一致的是 **Hy4 flash 的视觉塔**（27 层 / 1,152，SigLIP2-So400m 改版）。推断：商发分支当时对标的是内部同架构小模型的配置，**Hy4 正式版与 flash 两条视觉路径都需要核对**。
- **官方路径已开通**：vLLM-Ascend 官方插件仓库 11-02 合入 Hy4 部署指南（昇腾 950DT 单节点 / 多节点 / PD 分离，智东西报道）——与商发分支的 day0 工程互为印证，"内部商发 → 公开指南"的路径已经走通。
- **投机解码侧**：商发分支当前是 MTP 路径；开源正式版换成 **DFly2**（KV Share + Index Share）——NPU 侧若要享受"常数成本 draft"，需要评估 DFly2 的实现路径（这一项在 10 月分支里还不存在）。
- **量化侧**：商发分支验证的是 MXFP8（ModelOpt，~757.88 GiB）；公开提供的是 **FP8**（`Hy4-FP8`）与 GGUF（AngelSlim org）——口径需对齐后再做性能对比。

**本轮新增判断**：

> **⑳ "双模型结构"成型**：Hy4 保智能上限（770B-A49B、1M、Computer Use）+ flash 保日常成本（224B-A12B、KV 仅 1/6、150+ tok/s、成本 1/20）——官方已给出明确分工建议（日常用 flash、长程软件工程用 Hy4），且 flash 用"自蒸馏自 Hy4 + RL 削 50% 输出 token"实现了"小模型继承大模型智能"的闭环。**这是混元第一次把"旗舰+轻量"组织成产品化的双模型矩阵**。

> **㉑ "开源"的开放度在商业维度收窄**：preview/Hy3 是纯 Apache-2.0，正式版是带 MaaS 条款的 Tencent Hy License（$50M 营收 / 1 亿 MAU 门槛）。**权重开放 ≠ 商用自由**——"最强开源模型"的对外叙事与实际的商业条款是两条线，前者放大声量、后者控制杠杆。下游选型必须把 License 当作与技术同等的一等公民。

> **㉒ DFly2 让"稀疏注意力"从省算力变成"省投机成本"**：MTP 的 draft 成本随上下文增长，DFly2 因为共享 indexer 的 top-2048 选择，draft 成本恒定——**稀疏注意力的收益第一次从 prefill 延伸到 decode 的投机环节**。这让 DSA 类架构在 1M 上下文下的推理经济性进一步改善，也解释了为什么 FlashTopK 这类 selection 内核会成为基础设施。

## 九、结论

本窗口一句话：**混元把 11-04 的开源承诺全部兑现，并用 flash 把开源节奏拉回"两天"**。技术上三件事：① **DFly2 替代 MTP**，成为稀疏注意力旗舰的标准投机配置（KV+Index 共享、常数成本、PD 就绪）；② **flash 用 LatentMoE + Engram + 1:3 混合注意力**把日常任务成本压到 Hy4 的 1/20（WorkIndex 性能还略超 preview），"旗舰保上限、flash 保日常"的双模型结构成型；③ **HF 一次上架 20 个 WeMM-Video 仓库 + NVFP4 + FlashTopK SM100**，"Blackwell 就绪"成为隐性主题。

必须记录的暗线：**正式版权重的 License 从 Apache-2.0 收窄为带 MaaS 条款的 Tencent Hy License**（$50M 营收/1 亿 MAU 门槛，内部使用豁免）——"开源"的开放度在商业维度收紧，与"全部兑现"并行。

**Agent 侧本窗口增量很小**（UniRL 算法新增 AROPD，agentic 路径零改动；Hy-Memory 全线稳定性硬化；DiagSafe 扩到 reasoning 模型）——与推理侧的大动作形成鲜明对比，符合"模型代际发布窗口内 agent 侧静默"的节奏。

**昇腾侧**：权重已可拉取、官方 vLLM-Ascend 指南已合入，进入**实机验证与重同步窗口**（P0）；重点核对视觉塔规格（商发 27/1,152 vs 正式版 40/1,536，flash 反而对得上）与 DFly2 的 NPU 实现路径；对外服务前先过 License MaaS 条款（P0 合规）。
