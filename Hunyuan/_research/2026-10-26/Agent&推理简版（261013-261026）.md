## 一、总览

窗口内组织仓库 85 → 90（+5：Hy-Memory、Hy-Nomas、OmniCapBench、DiagSafe、HYDRA）。没有发布新旗舰 LLM；值得记的是两件大事 + 三件小事：

- ⭐ **Hy-Memory 2.0（10-16 发布）**：记忆做成"模型 + SDK + 应用（MemHub）"三层开源；
- ⭐ **Hy-Nomas（10-21）**：世界模型做成"可交互 + 可单卡跑 + 可服务化"的完整推理栈；
- WorkForge（10-22）：Agent 训练"可验证环境合成"（论文、非仓库）；AuK（10-14）：4 步蒸馏训练管线开源；UniRL v0.2.0（10-19）：打版、能力未新增；
- 平台侧收缩：元器 11-09 停服、QClaw 12-24 停运，Agent 出口收敛为 WorkBuddy + 企业微信 + 腾讯云 ADP。

## 二、⭐ Hy-Memory 2.0 —— 记忆三层开源

| 层 | 产物 | 要点 |
|---|---|---|
| 模型 | Hy-Memory-30B-A3B（HF 10-15） | 30B 总参 / ~3B 激活 MoE（Hy3 架构栈），专做"记忆写入"；FP8 / GGUF 两族；两阶段训练 = Memory OPD → Attributed Memory RL（教师 = Hy3 旗舰） |
| 框架 | hy-memory SDK（PyPI，2.0.5） | 三场景：chat（L0–L7 分层记忆）/ working（会话事实 + 可复用经验）/ coding（+ 零 LLM 版本演进 diff 链）；三档 lite/pro/ultra；只需 LLM + Embedding 两个 OpenAI 兼容端点，不绑定混元模型 |
| 应用 | MemHub（v1.0.x） | 本地优先共享记忆（macOS 公证 + Linux Runtime）；无 Windows；已接 Claude Code / Cursor / Codex / OpenCode / Qwen Code（IT之家称 10 种） |

**数字（口径务必看清）**：

- 跨 harness 记忆写入分：Hy-Memory **55.49** vs Claude Opus 5 的 54.62（固定 20% 子采样 + 六指标等权，差 0.87）——"记忆写入超 Opus 5"成立，不是通用能力；
- GGUF 用 imatrix + MoE 混合精度（路由专家压狠、共享专家/注意力/出入口保精度）：`Q8_0-expsIQ1_M` **8.03 GB 只掉约 1.5 分**；官方给完整 llama-server 配方，并在 H20 公开核验社区 Q1/Q2/TQ 超低比特档 **0/8 全挂** → "能加载 ≠ 能用"；
- 框架层自评（IT之家转述官方、无第三方复测）：MemoryArena 55.31%（+10.2pp）、LoCoMo 72.6%（每题 token −39.3%）、CodeMemoryBench 64.2%/35.6%、SWE-ContextBench 28.3%；官方 4 基准无 LongMemEval。

**对昇腾参考**：vLLM（v0.31.0）+ no_think / temperature=0 的低温度、短结构化 JSON 输出、高并发专用负载形态（与 chat 不同）；GGUF imatrix + MoE 混合精度量化配方可借鉴；低比特量化必须先做"能加载 ≠ 能用"核验。

## 三、⭐ Hy-Nomas —— 世界模型推理栈

- **定位**：世界生成 + 多轮指挥——逐段生成视频、每段可接受新指令/相机轨迹，持久 KV cache 保持跨段一致；输出是视频（非 3D）。Apache-2.0，★168。
- **架构**：54 层双流 dense MMDiT + DCAE-V（32× 空间 / 4× 时间压缩）+ 1 步解码 PixelUMM_FT + 8 步蒸馏（支持 4/6/8 步）；文本条件 Qwen2.5-VL-7B（PE 在线增强）；720×1280@24FPS。
- **单卡 RTX 4090 四开关**（⚠️ 标准预设是 SP8/8 卡，单卡需 sp_size=1 配置）：① INT8 权重 + INT8 KV（线性层仍 BF16 计算，加载后不能挂 LoRA）② 滑动窗口历史 18 latent frames ③ CPU offload ④ FlexAttention + CUTLASS FP8。
- **服务化**：gateway / dispatcher / GPU 资源池 / 任务持久化 / 尝试归档（replay）+ PE 提示增强服务（SGLang 跑 Qwen3.8，独立 GPU）；官方 Docker hynomasoss:cu130（CUDA 13）。
- **数字提醒**：24 FPS 是播放帧率不是生成速度；Hy-Nomas-Bench 280 用例只发题不发分；技术报告 Coming Soon——现无任何官方质量/吞吐数字，评估必须自建端到端时延基线。
- **对昇腾参考**：生成模型（视频/世界）服务化的现成参考架构；NPU 侧无世界模型推理路径（P0 立项评估）；其 SGLang PE 服务与现网 SGLang 生态直接相关。

## 六、结论

本窗口最有参考价值的就两件事——**Hy-Memory**（记忆做成"模型 + SDK + 应用"三层，为"记忆写入"这类专用负载立了 vLLM/GGUF 部署与量化样板）和 **Hy-Nomas**（世界模型做成可单卡跑、可服务化的完整栈，为"生成模型推理平台"立了架构样板）；其余（WorkForge / AuK / UniRL 打版 / 平台收缩）为背景增量。昇腾侧动作：新增 P0 立项评估（Hy-Nomas）、P0 PR 跟踪（DSpine），量化与评测方法论按 P1 借鉴。
